Browser Bridge Settings

All changes save instantly. Each switch spells out what On and Off do, marks the recommended position, and carries a tag for which way “On” leans: Protection keep on for safety · More access On grants the AI more power · Convenience no security impact.

Security

Allow page_eval (run arbitrary JavaScript)More access
On (default): page_eval is available to the AI — each call is still gated by the confirmation below. Off (safest): page_eval is refused outright, so no code can ever run on the page. This is the single most dangerous tool; turn it off if you never need it (ADR-0008).
Redact secrets in page_eval resultsProtection
On (default, recommended): mask token-like values in eval results — JWTs, long hex, long numbers, and strings that look like keys — before they reach the AI. Off: results are returned verbatim (ADR-0008).
⚠ Off: tokens, cookies, and keys in eval results can reach the AI unmasked.
Confirm high-risk clicks (submit buttons & links)Protection
On (default, recommended): clicking a submit button or a link pops a confirmation you must approve — the main guard against the AI silently placing an order, transferring funds, or navigating away. Off: those clicks run with no prompt (ADR-0006).
⚠ Off: the AI's clicks on submit buttons and links are no longer confirmed. Turn off only if you fully trust the AI.
Confirm every page_eval (arbitrary JS)Protection
On (default, recommended): each page_eval shows the full code and waits for your approval. Off: the AI runs arbitrary JavaScript with no prompt. page_eval is the highest-risk operation (ADR-0008).
⚠ Off: the AI executes arbitrary JS directly with no prompt. Turn off only if you fully trust the AI and want unattended automation.
Confirm before closing a tab (tab_close)Protection
On (default, recommended): a "Close tab?" prompt appears in the page and waits for your approval before tab_close runs. Off: tabs close with no prompt.
⚠ Off: the AI closes tabs directly with no prompt.
Notify before a precise snapshot (page_snapshot_precise)Protection
On (default, recommended): show a heads-up in the page before page_snapshot_precise runs (it uses chrome.debugger, so Chrome also briefly shows a "Debugging" banner at the top). Off: it runs with no heads-up (ADR-0009).

Tabs

Group AI-opened tabs togetherConvenience
On (default, recommended): tabs the AI opens via tab_open go into a named "Browser Bridge" group, kept visually separate from your own tabs so you can collapse or close them together. Off: they open loose among your tabs (ADR-0018).

Execution mode

Route all page actions through CDP (chrome.debugger)More access
Off (default, recommended): page actions inject a content script — the normal mode. On: everything runs through CDP (chrome.debugger) instead, which lets page_eval work on strict-CSP sites such as Bing (ADR-0017).
⚠ On: Chrome shows a persistent "Debugging this browser" banner (the debugger stays attached the whole time) and the access surface is larger. Turn on only to bypass CSP or for unified deep control.

Tool enablement

For any unchecked tool, an AI call receives a "tool disabled in settings" error. Note: the AI can still see that the tool exists, but cannot execute it.

Allowed sites (allowlist)

Allow all sites (skip per-site approval)More access
Off (default, recommended): the AI needs your approval the first time it touches each new site — use the allowlist below. On: the AI can act on any http(s) site immediately with no per-site prompt (this requests the "<all_urls>" host permission). Only turn on if you trust the AI to browse fully automatically.
⚠ On: any site — including banking, email, and intranet — can be acted on without approval. Use with care.
Format: https://domain/*. After adding manually, Chrome's host-permission prompt still needs to be approved on first visit to that site.
